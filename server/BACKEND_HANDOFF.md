## 1. Global API Conventions

### 1.1 Base URL & Content Type
- All API routes are prefixed with `/api`.
- Request body format: `application/json; charset=utf-8`.
- Response format: `application/json; charset=utf-8`.

### 1.2 Headers
| Header | Type | Description | Required? |
|---|---|---|---|
| `Content-Type` | `application/json` | For all `POST` and `PATCH` requests | Yes |
| `Idempotency-Key` | String (UUID / unique string) | Required on `POST /api/orders` and `POST /api/inventory/adjustments` to prevent duplicate mutation on retry | **Yes (on mutating POSTs)** |
| `X-Request-Id` | String (UUID) | Auto-generated by backend if not passed; returned on every response for tracing | Optional |

### 1.3 Currency Representation
- All monetary amounts are represented as **integer paise** (1 Rupee = 100 Paise) to avoid floating-point inaccuracies.
  - Example: `₹599.00` is represented as `59900`.
  - Format for display in UI: `(price_paise / 100).toFixed(2)`.

### 1.4 Response Envelopes

#### Standard Success Envelope
```json
{
  "success": true,
  "data": { ... },
  "message": "Operation completed successfully"
}
```

#### Paginated Success Envelope
```json
{
  "success": true,
  "data": [ ... ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 42,
    "totalPages": 5,
    "hasNext": true,
    "hasPrev": false
  },
  "message": "Items retrieved"
}
```

#### Standard Error Envelope
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      {
        "field": "body.price_paise",
        "message": "Price in paise must be a non-negative integer"
      }
    ]
  }
}
```

## 2. Standard Error Codes

| HTTP Status | Error Code | Meaning | User Action |
|---|---|---|---|
| `400` | `VALIDATION_ERROR` | Request payload, query parameter, or route parameter failed validation. | Inspect `error.details` for field-specific errors. |
| `400` | `BAD_REQUEST` | General bad request (e.g. malformed JSON). | Correct the request structure. |
| `400` | `MISSING_IDEMPOTENCY_KEY` | Missing `Idempotency-Key` header on required POST endpoint. | Generate a unique UUID header. |
| `400` | `INVALID_STATUS_TRANSITION` | Attempted invalid order status progression (e.g. Pending → Completed). | Check status machine rules. |
| `400` | `INSUFFICIENT_STOCK` | Order item quantity exceeds current available stock. | Show out-of-stock warning in UI. |
| `400` | `INVALID_OPERATION` | Business constraint violation (e.g. adjusting stock below 0, ordering archived product). | Show user alert. |
| `404` | `NOT_FOUND` | Resource not found (product, order, category). | Redirect to list or show 404 state. |
| `409` | `CONFLICT` | Unique constraint violation (e.g. duplicate SKU) or idempotency payload mismatch. | Prompt user with duplicate message. |
| `422` | `INVALID_REFERENCE` | Foreign key reference failure (e.g. non-existent `category_id`). | Select a valid category. |
| `500` | `INTERNAL_ERROR` | Unexpected server error. | Display generic error banner; check logs with `X-Request-Id`. |

## 3. Order Status State Machine

Orders must transition strictly according to the following directed graph:

```text
       ┌──────────┐
       │ Pending  │
       └────┬─────┘
            │
      ┌─────┴───────────────┐
      │                     │
      ▼                     ▼
┌───────────┐         ┌───────────┐
│ Confirmed │         │ Cancelled │ (Terminal — Stock restored atomically)
└─────┬─────┘         └───────────┘
      │                     ▲
      ├─────────────────────┘
      ▼
┌───────────┐
│ Completed │ (Terminal — Revenue realized)
└───────────┘
```

- **Pending**: Order placed, stock deducted, awaiting review/payment.
- **Confirmed**: Order accepted, ready for fulfillment.
- **Completed**: Order delivered/fulfilled. Counted toward dashboard revenue.
- **Cancelled**: Order cancelled. **Stock is automatically restored once**.
- **No-op idempotence**: Submitting the same status that the order already has returns the existing order safely without making redundant transitions or stock modifications.

#### `POST /api/orders`
Create a new multi-item order.
- **Required Header**: `Idempotency-Key: <unique-uuid-or-key>`
- **Request Body**:
```json
{
  "customer_name": "Rohan Sharma",
  "items": [
    { "product_id": 1, "quantity": 1 },
    { "product_id": 2, "quantity": 1 }
  ]
}
```
- **Rules**:
  - `items` must not be empty.
  - Duplicate `product_id`s in the array are rejected with `400`.
  - Stock is validated and deducted atomically across all items.
  - Unit price is snapshotted from the database directly (client cannot submit custom price).
- **Response `201`**: Full order object with calculated items and totals.

#### `PATCH /api/orders/:id/status`
Update order status according to the state transition matrix.
- **Request Body**:
```json
{
  "status": "Confirmed"
}
```
- **Allowed values**: `'Pending'`, `'Confirmed'`, `'Completed'`, `'Cancelled'`.
- **Note**: Transitioning to `'Cancelled'` automatically restores stock for all items and writes `cancellation_reversal` stock movements.
- **Response `200`**: Updated order object.

#### `POST /api/inventory/adjustments`
Manually increase or decrease product stock with mandatory audit reason.
- **Required Header**: `Idempotency-Key: <unique-uuid-or-key>`
- **Request Body**:
```json
{
  "product_id": 1,
  "delta": 5,
  "reason": "Damaged goods replacement received from vendor"
}
```
- **Rules**:
  - `delta` can be positive (stock addition) or negative (stock reduction), but cannot be `0`.
  - Resulting stock (`stock_quantity + delta`) cannot be negative.
- **Response `200`**:
```json
{
  "success": true,
  "data": {
    "product_id": 1,
    "product_name": "Wireless Optical Mouse",
    "previous_stock": 42,
    "resulting_stock": 47,
    "delta": 5,
    "movement_id": 17,
    "reason": "Damaged goods replacement received from vendor"
  },
  "message": "Stock adjusted successfully"
}
```

## 5. TypeScript Definitions for Frontend

Copy and paste these interfaces into your React project (e.g. `src/types/api.ts`):

```typescript
export interface ApiResponse<T> {
  success: boolean;
  data: T;
  message?: string;
}

export interface PaginatedResponse<T> extends ApiResponse<T[]> {
  pagination: {
    page: number;
    limit: number;
    total: number;
    totalPages: number;
    hasNext: boolean;
    hasPrev: boolean;
  };
}

export interface ApiErrorResponse {
  success: false;
  error: {
    code: string;
    message: string;
    details?: Array<{ field?: string; message: string }>;
  };
}

export interface Category {
  id: number;
  name: string;
  created_at: string;
}

export interface Product {
  id: number;
  name: string;
  sku: string;
  category_id: number;
  category_name?: string;
  description?: string | null;
  price_paise: number;
  stock_quantity: number;
  low_stock_threshold: number;
  is_active: number; // 1 = active, 0 = archived
  created_at: string;
  updated_at: string;
}

export type OrderStatus = 'Pending' | 'Confirmed' | 'Completed' | 'Cancelled';

export interface OrderItem {
  id: number;
  order_id: number;
  product_id: number;
  product_name: string;
  product_sku: string;
  quantity: number;
  unit_price_paise: number;
  line_total_paise: number;
}

export interface OrderStatusHistory {
  id: number;
  order_id: number;
  previous_status: OrderStatus | null;
  new_status: OrderStatus;
  created_at: string;
}

export interface Order {
  id: number;
  order_number: string;
  customer_name: string;
  status: OrderStatus;
  total_paise: number;
  item_count?: number;
  created_at: string;
  updated_at: string;
  items?: OrderItem[];
  status_history?: OrderStatusHistory[];
}

export type MovementType = 'initial' | 'sale' | 'cancellation_reversal' | 'adjustment';

export interface StockMovement {
  id: number;
  product_id: number;
  product_name: string;
  product_sku: string;
  movement_type: MovementType;
  quantity_delta: number;
  previous_stock: number;
  resulting_stock: number;
  order_id?: number | null;
  order_number?: string | null;
  reason: string;
  created_at: string;
}

export interface DashboardSummary {
  total_active_products: number;
  total_orders: number;
  total_completed_revenue_paise: number;
  low_stock_products_count: number;
  out_of_stock_products_count: number;
  recent_orders: Array<{
    id: number;
    order_number: string;
    customer_name: string;
    status: OrderStatus;
    total_paise: number;
    created_at: string;
  }>;
  daily_sales_trend: Array<{
    date: string;
    order_count: number;
    revenue_paise: number;
  }>;
}
```
